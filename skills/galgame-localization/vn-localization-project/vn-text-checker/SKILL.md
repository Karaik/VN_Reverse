# 译稿检查器

先读本作导出与回填代码，各取一份真实原文和译稿。列出正式输入中各类文本的记录键、字符串解码方式、引擎控制符和动态参数。沿用已有解析函数，按载体选择规则。

## 默认程序规则

默认采用 R1–R4。每次检查以该作品启用的规则为准。任务明确只做四项时，就只启用下表四项。

| 规则 | 判定依据 |
| --- | --- |
| R1 原译对应 | 在本作定义的文件、记录类型和编号范围内核对原文。报告未知、缺失或重复的记录。只有回填器依赖顺序时才检查顺序。独立编号的正文和选项可以使用相同数字。部分回交按选定文件检查其内部记录。 |
| R2 引擎控制符 | 在解码后的显示字段中检查本作的控制语法和受保护的参数。换行能否移动或增减、注音基字数如何表示，都从本作的回填器与实际脚本确认。 |
| R3 字符串读入 | 使用回填器实际接受的标记行、引号、转义和物理行规则。支持省略外层引号的格式应同时通过有引号和无引号的合法样例。解析失败时指出条目或物理行。 |
| R4 动态参数 | 在实际执行格式化或插值的系统字符串中，核对参数的名称、数量、类型和本作要求的顺序。逐条比较格式串，区分游戏正文中的字体命令与系统提示里的 printf 参数。 |

检查器只读正式原文和译稿。报告给出规则、相对文件名、行号或记录键，以及触发原因。

## 按作品扩展

- **沿用本作的检查入口。** 虫爱本篇的 `CheckerPipeline` 分别调用格式检查和符号检查。虫爱 FD 用 `CheckerProfile` 选择每行上限，默认 24 字，《虫狂篇》为 34 字。同一算法的阈值可以放进作品配置。需要另一种判定时，再加独立规则并接入现有入口。新增规则按作品需求启用。
- **写清触发位置和合法例外。** 例如要求换行前有标点时，只看正文中实际存在的换行点。先按本作脚本识别说话人和台词的分隔，再检查正文。末段缺标点可由句尾规则报告。同一条台词里两次换行都违规时，报告列出两个位置，汇总时分别统计受影响的记录数和命中次数。行宽或缩进规则还应写清计算单位、可见文本范围，以及对白、旁白和选项各自适用的条件。
- **检测、统计和修正分别启用。** 《真爱百合》的 `rules.toml` 用 `[check]` 和 `[rewrite]` 配置不同动作。`W005` 检查对白续行缩进，`I001` 统计显示行数，`R003` 在报告中给出缩进修正候选。扩展时沿用项目已有的规则编号。需要回写的项目可在报告中提供候选，由操作者通过 `patch` 等现有入口显式应用。

## 验证

在项目正常入口跑完整译稿，记录文件数和实际发现。另取真实文件的临时副本，每条规则各制造一个已知错误，核对报告的位置和规则，再修回副本复查。用真实格式中的合法变体作对照，例如同号不同类型的记录、可选外层引号或可移动的换行。验证前后核对正式输入的内容一致。

验证扩展规则时，用容易混淆的一对真实样例，例如“旁白续行多一格”和“对白按原版缩进一格”。关闭新规则时比对原有报告，只在一作启用时核对其他作品的结果。提供自动修正的规则还要在副本上回填，对比修改是否只落在命中的位置。
