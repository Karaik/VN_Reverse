# 视觉小说汉化项目

适用于建立、整理或扩展具体游戏的汉化流水线。

## 开始

- 先确认作品、发行版本和本次交付范围。搭建、迁移或修改打包流程时查阅 [流水线说明](references/pipeline.md)，已有工程沿用正在使用的译稿格式、资源目录和入口。
- 收到译稿或美工回图时，可直接查 [文本提取与回交](references/pipeline.md#文本提取与回交) 或 [图片交付与回写](references/pipeline.md#图片交付与回写)。
- 为作品添加或验证程序侧的只读译稿检查时，使用子技能 [译稿检查器](vn-text-checker/SKILL.md)。
- 构建清理只处理本构建器已认证的旧生成产物，保留本地原版、译文、静态资源、缓存输入、未知手工文件和原有存档。执行边界见 `references/build-cleanup.md`。
- 将已有可运行补丁视为行为基线，围绕它迁移执行链，不凭空猜测覆盖范围。

## 必需流程

1. 以本次目标游戏为准，确认与任务有关的引擎、资源格式、编码和加载方式。
2. 用项目相对路径定位正式输入和输出。系统工具链和用户提供的原版位置按项目约定配置。
3. 建立新脚本链时，先验证能否稳定定位和改写文本。只更新已有译稿或修图时，直接走本作已有的构建入口。
4. 从实际加载的脚本核对显示字段，再验证编辑、回填和读回。已有可靠补丁的版本适配，优先验证受影响的资源与引用。
5. 核对目标游戏实际加载的脚本、图片和补丁路径，再确定需要构建或复用的运行时组件。
6. 实现时同步编写结构与用法文档。
7. 每次构建在产生新的完整游戏副本或包之前清理旧生成产物；先验证完整清理计划，再执行受限删除，并排除本次运行。
8. 关键阶段都通过回归验证后，才能报告完成。
9. 开发期间按项目约定管理正式构建输入和旧补丁兼容基底。可重建的 EXE、DLL 和发布包放在输出目录。
10. 所有汉化项目在最终版发布前不久或发布后都必须完成[最终发布与归档](references/pipeline.md#最终发布与归档)。先验收最终补丁，再提交移除可编辑剧本文本的改动，从该提交发布最终 GitHub Release，最后归档作品仓库。多作品项目在全部计划作品收尾时执行。

## 固定规则

- 使用 `scripts/build_cleanup.py` 或满足相同边界的实现清理旧输出；禁止整删输出根、临时根或输入缓存。
- 默认仅清理显式输出根下顶层、名称可识别、标记和清单证明由本构建器生成的旧目录；未认证内容保留。
- 严格解析项目内路径，拒绝根目录、受保护输入、异常名称、越界、符号链接、联接点和重解析点；先完整预检，再通过同一 Python 进程删除。
- 构建入口必须提供 `--keep-previous-outputs` 和 `--dry-run`；预览之后不再产生新完整副本。不安全路径或清理失败必须中止构建。
- 测试存档和日志只可在一次性生成副本内以明确文件或子树登记为 `mutable_paths`；不得登记原版或用户保留的存档。
- 用 `generated_output(...)` 独占新建本轮输出目录，并在正常或异常退出时封存实际清单，使普通构建失败的半成品可在下一轮清理；不得认领历史未知目录。JSON 标记是可信本地流程约定，不抵抗恶意伪造。
- 最终维护流程不得硬编码外部项目绝对路径；用法示例使用相对路径。
- 文件名称简短明确，代码注释简洁且服务于实现。
- 新工具的开发日志使用英文。译校报告和面向汉化人员的提示沿用项目既有语言与格式，说明文档使用中文。

## 脚本与编码

- 从源结构核对正文、显示名、选项及系统界面的覆盖范围。沿用已有编号和字段映射，按实际显示位置从成品读回译文。
- 目标包括完整指令级逆向时，同时提供结构化 JSON 和可读指令源码。只需汉化时，可采用已验证的文本字段回写或资源覆盖，并注明支持范围。
- 支持变长的回写应重算受影响的长度、偏移和表项。固定长度字段按实际编码后的字节数检查容量。
- 按目标版本实际读取文本的编码回写。采用 `gbk` 时记录转换方式，验证中文、控制码和无法编码的字符。
- 工程使用 `filter_text.txt` 做混合编码回写时，按项目约定读取和匹配，回归覆盖命中与未命中两种情况。

## 运行时与文档

- 自研运行时记录源码构建入口。沿用旧补丁二进制时，记录原始来源、适用版本和文件摘要，有对应的上游源码时附固定提交链接。
- 复用已有可靠补丁布局，围绕该布局驱动工具。
- 清楚说明二进制结构；需要 Mermaid 时保持图示最小且语法有效。
- 来源说明使用永久上游链接。
- 游戏 README 提供构建与维护入口。已有发布首页时，从首页链接开发笔记，记录依赖、补丁输入、增量更新、输出位置及清理开关。

## 项目生成器

```powershell
python .\skills\galgame-localization\vn-localization-project\scripts\generate_title_layout.py ".\titles\sample-vn"
```

该模板包含 `translated_script/scn/` 和 `patch/base/chs_patch/`。需要这套布局时使用生成器。给已有工程接入清理功能时，可单独取用 `scripts/build_cleanup.py` 和接入说明。生成器保留已有文件。
