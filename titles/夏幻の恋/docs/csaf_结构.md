# CSAF 结构

本页只保留 `CSAF` 资源包格式、资源识别逻辑、命名恢复依据、目录恢复依据，以及已确认/未确认结论。

## 包结构

### 头部

| 偏移 | 类型 | 名称 | 说明 |
|---|---|---|---|
| `0x00` | `char[4]` | `magic` | 固定 `CSAF` |
| `0x04` | `u32` | `version_flags` | 低 31 位版本，最高位为加密标志 |
| `0x08` | `u32` | `file_count` | 文件数量 |
| `0x0C` | `u32` | `extra_size` | 扩展区长度 |
| `0x10` | `byte[16]` | `md5` | 目录区 + 扩展区校验 |

### 目录项

单条目录项长度 `24` 字节：

- `hash[16]`
- `start_block`
- `size`

### 布局

1. Header
2. Entry Table
3. Table Padding
4. Extra Region
5. 4KB Data Blocks

## 运行时载荷层

当前已确认：

- 运行时真实载荷不是直接使用包内原始块
- 读取块后还会做运行时变换
- 当前正式实现已经把这层变换收进封包实现层

## 资源识别逻辑

资源识别已经进入正式实现，不再只是“猜扩展名”。

当前正式规则包括：

- `NBDA` -> `script`
- PNG 头 -> `image`
- `OggS` / `RIFF...WAVE` -> `audio`
- 文本布局特征 -> `layout`
- 表格文本特征 -> `table`
- 其余 -> `payload`

识别结果的作用是：

- 决定资源在最终树中的类别归属
- 决定资源在清单中的 `resource_category`
- 决定未恢复原名资源应先落到哪一类占位位置

## 命名恢复依据

当前正式名字恢复依据分为这几类：

- 包内目录项
- 运行时路径
- 系统表
- 外部索引
- 脚本引用
- 其他来源

说明：

- 包内目录项只直接提供 hash / block / size
- 原始名字本身不是直接明文存于目录项
- 正式实现会把外部索引、运行时路径、系统表、脚本引用统一汇总成名字恢复框架

## 目录恢复依据

当前目录恢复规则是：

- 能恢复原始路径的资源，直接回到原始目录
- 还不能恢复原名的资源，先回到各自资源根
- 资源根下再按状态标记分层

当前正式状态标记：

- `待补原名`
- `待补原目录与原名`

因此默认输出已经是：

- `adv/...`
- `bg/...`
- `BGM/...`
- `ch/...`
- `ev/...`
- `SE/...`
- `song/...`
- `system/...`
- `voice/...`

而不是一棵树外的总 `unknown/` 目录。

## 已确认结论

- 默认输出已经是原始资源树导向，而不是 hash 平铺
- 资源识别已进入正式实现层
- 名字恢复框架已进入正式实现层
- 剧情脚本可从资源树 `adv/` 直接进入脚本链

## 未确认结论

- 并非所有资源都已经恢复原名
- 并非所有资源都已经恢复到最终原始目录
- 仍有一部分资源只恢复到“资源根 + 状态标记”这一层
