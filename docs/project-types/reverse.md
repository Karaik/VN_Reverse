# 逆向项目规则

## 适用范围

适用于以“确认格式、建立 roundtrip、沉淀结构文档”为目标的 title 项目。

典型信号：

- 目录内以 `*_decompile.py`、`*_compile.py`、`*_pack.py`、`*_unpack.py` 为主
- 存在 `regression_test.py`
- 存在 `docs/*_结构.md`
- README 关注格式、字段、回环、验证与限制

## 目标

逆向项目的完成标准是：

- 样本格式已确认到足以支撑工具实现
- 反编译和编译能覆盖文本处理
- 资源解包与回封可以验证
- 结构文档和验证结论可复查

它不默认要求交付最终汉化包，也不默认要求 runtime 打补丁。

## 推荐目录

逆向项目不强制统一成一种根目录模板，但应满足以下原则：

- 根目录保留少量清晰入口脚本
- 实现代码按语义分层放在稳定目录中
- `docs/` 存放结构、算法、限制、验证结论
- `regression_test.py` 或等效入口集中验证主链路

### 旧项目兼容原则

- 已经形成稳定用法的旧项目，可以继续保持根目录平铺入口脚本的形态。
- 只要 README、默认命令、验证链路仍然清楚，不要求为了形式统一而回头大搬家。
- 但后续新增实现时，不建议继续无限制往根目录平铺。

### 新项目建议

新建逆向项目时，推荐采用“根目录保留入口，新增实现按语义追加目录”的方式。

意思不是强制上 `solution/` 模板，而是：

- CLI 入口继续留在根目录
- 复杂实现、分析代码、共用逻辑逐步沉到子目录
- 随着项目变复杂，用追加结构把根目录的平铺增长截住

一个推荐形态可以是：

```text
title-root/
  README.md
  <format>_decompile.py
  <format>_compile.py
  <archive>_unpack.py
  <archive>_pack.py
  regression_test.py
  docs/
  script/
  archive/
  common/
  analysis/
```

如果项目规模较小，也可以把 `script/`、`archive/`、`common/` 合并成一个语义明确的实现目录。

### 追加结构原则

- 根目录只保留直接入口，不继续堆实现细节。
- `script/` 放脚本解析、反编译、编译、文本处理相关实现。
- `archive/` 放封包、解包、清单、压缩相关实现。
- `common/` 放二进制读写、常量、共享模型、公共工具。
- `analysis/` 放审计、探针、实验性分析与辅助脚本。

重点不是目录名必须完全一样，而是新增加的复杂实现应有稳定归宿，而不是继续把根目录铺满。

## 必须交付的能力

如果脚本格式是可编辑指令型，至少提供：

- JSON 形态
- 可读的指令源码形态

并满足：

- unchanged roundtrip 可验证
- 文本变长后仍可回编
- 长度、偏移、索引等相关元数据会被重算

如果只完成“能看不能回写”，项目仍应视为未完成。

## 文档要求

逆向项目至少应写清：

- 文件头与字段定义
- 偏移、长度、索引表等关键结构
- 编码策略
- 工具入口与参数
- 当前已验证结论
- 仍未确认的部分

## 验证要求

最少应覆盖：

- 脚本反编译 -> 回编
- 指令源码导出 -> 回编
- 文本变长回归
- 封包解包 -> 回封

如果格式不适合做字节级一致，也要给出结构等价或二次反编译一致的验证标准。

## 困难脚本止损规则

逆向项目默认以“建立可编辑 roundtrip”为目标，但并不是所有脚本都值得继续朝“完整反编译器 + 完整编译器”硬顶。

一旦出现下面这些信号，就不要再把“完整脚本重构”当成当前阶段主目标：

- 控制流高度依赖状态机、分发表、间接跳转或大量上下文状态
- 文本可以定位，但 CFG 和 handler 语义长期无法稳定收敛
- 已经能识别文本载体和引用关系，但无法在合理成本内完成完整回编
- 继续投入的主要收益只是“更优雅的逆向结果”，而不是“更快到达可汉化”

这时应立刻停止继续扩张脚本本身的重构逆向，把目标切换为“汉化优先的可维护 patch 方案”。

详细策略见：

- `docs/workflows/hard-script-pivot.md`

## 转向后的原则

- 优先保持原控制流，只解决文本可替换、可重定向、可验证。
- 先选对现有执行链侵入最小的方案，再考虑更漂亮的完整编译器。
- 每种 patch 方法都要写清前提、限制、失败条件和验证方式。
- 当下目标改为“可交付汉化”，不再把“完整 script IR”作为阻塞项。

## 不要混入的内容

- 不要把最终补丁打包、runtime 注入、发布物布局当成默认目标。
- 不要把某个汉化项目的固定目录模板强行套到所有逆向项目上。
- 不要用 README 承载长期的 AI 执行记忆或阶段聊天记录。
